## Дополнительный вход API2

20.09.2026 подключён `api2-tyumen.delosud.ru`: DNS A → `195.19.66.234`,
DNS only, TTL 300, отдельный nginx vhost `delosud-gw-tyumen` и сертификат
Let's Encrypt до 19.12.2026. `certbot.timer` активен, `nginx -t` прошёл;
прежние виртуальные серверы сохранены побайтно.

API2 проксирует запросы к существующему `api-tyumen.delosud.ru`; новые ключи,
Worker и данные не создаются. Вход владельца и оператора, разграничение ролей
и CORS проверены без VPN. Это отдельная ссылка, автоматические fallback-адреса
дашборда и исполнителей не менялись.

Отдельный сервис `court-monitor-upload-tyumen.service` включён и работает
на `127.0.0.1:8787`. В Worker через Cloudflare UI опубликовано
`IMPORT_GATEWAY_ORIGIN="https://api2-tyumen.delosud.ru"`. Обратная загрузка
использует gzip и буферизацию nginx. Пробы с 1 КиБ, 400 КиБ и 2 МиБ
повторяющегося текста дошли до ожидаемой валидации домена (400) с точным SHA-256;
данные в очередь не добавлялись. Это не гарантирует передачу каждого большого
файла: 400 КиБ разнообразного текста (308 109 байт после сжатия) на итоговой
конфигурации дали 502 по таймауту Worker через 20 секунд. Ограничение передачи
крупных плохо сжимающихся дампов сохраняется. Успешный вход в операторскую
не подтверждает полный рабочий цикл без VPN для всех файлов.
Локально прошли 17 тестов сервиса
и 58 тестов шлюза Worker. Подробности и порядок отката —
в [документе API2](../../docs/regions/Тюмень_api2.md).

из таблицы и `LLM_PROVIDER=openrouter`. В исходном `dashboard` список Variables

Ручной workflow `verify_tyumen_setup.yml` завершился успешно:
[проверка подключения №35501447891](https://github.com/SelivanovAS/dashboard-tyumen/actions/runs/35501447891).
Проверены Telegram `getMe` и `getChat` с типом `private` и совпадением заданного
chat ID, OpenRouter `GET /api/v1/key`, Worker `GET /import-pending`
с Bearer `PUSH_SECRET`. Сообщения не отправлялись, модель не вызывалась.

`TELEGRAM_CHAT_ID_TEST` задаёт личный чат пользователя с существующим ботом.
Корпоративный `TELEGRAM_CHAT_ID` не используется; доставка согласована только
пользователю. Секреты Worker и GitHub заданы отдельно. GitHub `PROGRESS_SECRET`

последний первым. Отдельный `progress_token.tyumen` на VPS сохранён.

## VPS и расписание

Вход `root` по ключу Mac работает. Deploy key `dashboard-tyumen@vps` сохранён
в GitHub с правом `Read/write`, fingerprint проверен. С VPS успешно выполнены
`git pull` и `git push --dry-run`; доступ к чтению и публикации подтверждён.

Настройка выбора `deploy_tyumen` ограничена новым клоном:

```sshconfig
Match host ssh.github.com exec "test $(pwd) = /opt/court-monitor/dashboard-tyumen"
  IdentityFile ~/.ssh/deploy_tyumen
  IdentitiesOnly yes
```

В `~/.config/court-monitor` подготовлены файлы с правами `0600`:

- `env.tyumen`: `REGION=tyumen`, собственный `DASHBOARD_URL`, `BANK_TRACK=1`
  и разрешённые параметры отбора из конфигурации Башкортостана;
- `worker.tyumen`: собственные `url=`, `owner_secret=`, `push_secret=`;
  файл читается как данные, не через `source`;
- `progress_token.tyumen`: отдельный токен прогресса Тюмени.

20.09.2026 путь `/opt/court-monitor/dashboard-tyumen` добавлен четвёртым
в `territories`. Прежние три территории сохранены; резервные копии списка

## Границы проверки

- Worker `GITHUB_PAT` не задан: недоступны связанные статусы Actions и ручной
  GitHub dispatch из админки. Автоматическое расписание VPS и replay после
  Git push от этого не зависят.
- Отдельный шлюз загрузки включён через `IMPORT_GATEWAY_ORIGIN`, но успешные
  синтетические пробы не подтверждают прохождение каждого большого файла:
  для крупного плохо сжимающегося дампа воспроизведён таймаут. Реальный
  операторский импорт без VPN ещё не проверен.
- Первый полный прогон, фактическая доставка Telegram/Web Push и операторский
  импорт будут проверяться на первичных данных; они не имитировались.
  Проверка авторизации не подтверждает генерацию модели или доставку уведомлений.
- Прямые карточки местных судов пока не проверены: исходных URL карточек
  нет. HTTP 200 от сайта сам по себе не подтверждает чтение такой карточки.
